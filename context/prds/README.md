# Product requirements documents

PRDs describe user needs, scope, and observable behavior. Keep one file per meaningful feature or product change and link it here.

## PRDs

- [Signup form](signup-form.md) — signup form and server-side payload validation.

## Writing a PRD

1. Start from [the PRD template](TEMPLATE.md).
2. State the problem and intended outcome before describing implementation.
3. Make requirements testable through observable behavior.
4. Call out exclusions and unresolved questions explicitly.
5. Update this index when adding a PRD.

Add a focused PRD here for each signup feature as it is selected for implementation.
